# Session data model

Every capability run creates a session directory under the workspace. This
document describes the files written to each session and their schemas.

## Directory layout

```
<workspace>/<session-id>/
├── session.json          # Session metadata
├── events.jsonl          # Tamper-evident event log
├── findings.json         # Generated findings
├── graph.json            # Attack graph edges and nodes
├── interesting.json      # Interesting graph summary
├── outcome.json          # Post-execution outcome
├── cleanup.json          # Rollback state ledger
└── vault/
    ├── index.json        # Vault item index (redacted metadata)
    └── *.vault           # Fernet-encrypted secret blobs
```

## session.json

Written at session creation. Schema version 2.

```json
{
  "schema_version": 2,
  "session_id": "20260823T141500Z-a1b2c3d4",
  "correlation_id": "f47ac10b58cc4372a5670e02b2c3d479",
  "created_at": "2026-08-23T14:15:00+00:00",
  "tool": "adaf-attack",
  "root": "/home/operator/.local/share/adaf-attack/workspaces/20260823T141500Z-a1b2c3d4",
  "audit_integrity": "sha256-chain"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `schema_version` | int | Always `2` for the current format |
| `session_id` | string | `YYYYMMDDTHHMMSSZ-<8-hex>` timestamp + random suffix |
| `correlation_id` | string | Full UUID4 hex for correlating events across subsystems |
| `created_at` | string | ISO 8601 UTC timestamp |
| `tool` | string | Always `"adaf-attack"` |
| `root` | string | Absolute path to the session directory |
| `audit_integrity` | string | Hash-chain algorithm; currently `"sha256-chain"` |

## events.jsonl

Append-only event log with a SHA-256 hash chain. Each line is a
self-contained JSON object. Events are `fsync`'d to disk and the file
is permission-restricted to `0o600`.

### Event schema (version 2)

```json
{
  "event_schema_version": 2,
  "ts": "2026-08-23T14:15:01.123456+00:00",
  "type": "run.start",
  "correlation_id": "f47ac10b58cc4372a5670e02b2c3d479",
  "prev_hash": "",
  "event_hash": "a1b2c3d4...",
  "capability": "ldap-enum",
  "domain": "corp.local",
  "dc_ip": "10.0.0.10"
}
```

### Reserved audit fields

These fields are set by the `Session.log()` method and cannot be
overridden by event payload:

| Field | Description |
|-------|-------------|
| `type` | Event type (e.g., `run.start`, `run.complete`, `run.error`, `cleanup.registered`, `approval.accepted`) |
| `ts` | ISO 8601 UTC timestamp (set at log time) |
| `event_schema_version` | Always `2` |
| `correlation_id` | Inherited from the session |
| `prev_hash` | SHA-256 hex of the previous event (empty string for the first event) |
| `event_hash` | SHA-256 hex of this event (computed over all fields except `event_hash` itself) |

### Hash chain verification

The hash chain provides tamper evidence. Each event's `prev_hash` must
match the preceding event's `event_hash`. The unsigned event is
serialized with `json.dumps(event, sort_keys=True, separators=(",",":"))`
before hashing.

Verify a session's event log:

```python
from adaf_attack.core.session import verify_event_log

result = verify_event_log("path/to/events.jsonl")
# {"ok": True, "events": 42, "last_hash": "abc123..."}
```

Or from the CLI:

```bash
adaf-attack session verify --session ./workspaces/<session-id>
```

### Common event types

| Type | When |
|------|------|
| `run.start` | Capability execution begins |
| `run.complete` | Capability execution succeeds |
| `run.error` | Capability execution fails |
| `cleanup.registered` | A rollback entry is recorded |
| `approval.accepted` | A scoped approval token is verified |

## findings.json

Generated by `findings_from_session()` after a capability run. Contains
rule-based findings derived from session evidence.

```json
{
  "schema_version": 2,
  "session_id": "20260823T141500Z-a1b2c3d4",
  "findings": [
    {
      "id": "FIND-001",
      "severity": "high",
      "title": "Kerberoastable service account",
      "evidence": [
        {
          "type": "spn_account",
          "value": "svc_backup@corp.local",
          "hash": "sha256:abc123..."
        }
      ]
    }
  ]
}
```

Findings include artifact hashes for evidence integrity. The MITRE ATT&CK
and NIS2 mappings in `src/adaf_attack/mappings/` enrich findings with
technique references.

## graph.json

The attack graph serialized as nodes and weighted edges. Edge types and
weights are defined in `core.graph.EDGE_WEIGHTS` (35+ edge types).

## cleanup.json

Array of rollback entries registered by destructive capabilities via
`session.register_cleanup()`. Each entry records the pre-change state and
classification.

```json
[
  {
    "kind": "ldap-attribute",
    "target": "CN=victim,DC=corp,DC=local",
    "attribute": "msDS-AllowedToActOnBehalfOfOtherIdentity",
    "previous": null,
    "status": "pending",
    "classification": "revertable",
    "registered_at": "2026-08-23T14:15:30+00:00"
  }
]
```

| Field | Description |
|-------|-------------|
| `kind` | Rollback kind (see [ROLLBACK_MATRIX.md](ROLLBACK_MATRIX.md)) |
| `target` | DN or identifier of the modified object |
| `attribute` | LDAP attribute modified (when applicable) |
| `previous` | Original value before the change |
| `previous_hex` | Hex-encoded original value (for binary attributes) |
| `status` | `pending` · `completed` · `failed` |
| `classification` | `revertable` · `advisory` |
| `registered_at` | ISO 8601 UTC timestamp |
| `artifact` | Path to a saved artifact (when applicable) |
| `host` | Hostname (when the change is host-scoped) |

## SessionStore (sessions.sqlite)

A workspace-level SQLite index over all sessions. Not part of the session
directory itself — it lives at `<workspace>/sessions.sqlite`. The index
is a cache that can be rebuilt from the session directories.
